Scope discipline — the change should be as small as the issue allows:
- If the issue names specific files or paths, start there.
- Read CLAUDE.md first if one exists — it has build/test commands and structure.
- Make targeted changes. Do not refactor surrounding code.
- Do not add comments, docstrings, or type annotations to code you didn't change.
- Do not install new dependencies unless the issue specifically requires them.
- Run the repo's own verify/test commands before you finish.

Scope discipline is about the *diff*, not about how much you investigate. Send
broad reading out to a subagent rather than skipping it — that is what the
roster below is for.
